# Design

## Context

CloudTube is a Vite + React + TypeScript app deployed as a Cloudflare Worker. There is
no test runner beyond `tsx --test` for unit tests, no GitHub Actions, and no PR template.
`AGENTS.md` already defines the delivery rules (L4 autonomy, `npm run release:patch` on
every push, `npx tsc --noEmit` + `npx vite build` as verification). The template must
extend those rules, not restate a generic checklist.

The issue asks for three practices to be encoded: OpenSpec for planning, lever for
autonomy, and the harness starter kit for durable rules and evidence. It also asks for
Playwright screenshots as proof of work.

## Goals / Non-Goals

**Goals:**

- One template that an agent can fill mechanically and a human can review at a glance.
- Make the OpenSpec and lever instructions real: a `openspec/` scaffold exists and the
  autonomy dials file is already tracked at `.openhands-setup/lever.yml`.
- Playwright runs locally with no download: the sandbox ships Chromium at
  `/usr/bin/chromium`, and Playwright's packages have no postinstall script, so adding
  `@playwright/test` keeps `bun install --frozen-lockfile` (the Cloudflare build step)
  working.
- Produce a committed screenshot of the rendered template plus an app-boot screenshot.

**Non-Goals:**

- No CI workflow. The repo has no GitHub Actions today; adding one is a separate change
  with its own review.
- No runtime, API, or UI behaviour change.
- Not installing the full OpenSpec skill set into `.agents/` — the scaffold is enough for
  the template's commands to resolve.

## Decisions

- **Keep the template as plain markdown, no YAML frontmatter.** GitHub only supports
  frontmatter on issue templates, not PR templates. Section headings are the contract.
- **`skip_specs: true` for this change.** Adding a template changes no system behaviour,
  so `openspec validate --strict` accepts zero deltas instead of forcing an invented
  requirement.
- **Playwright resolves the browser in a fallback chain** (`PLAYWRIGHT_EXECUTABLE_PATH`,
  then `/usr/bin/chromium`, then the managed browser) so the same spec runs in this
  sandbox and in a future CI runner after `npx playwright install chromium`.
- **The e2e test asserts the template's own content** and renders it through GitHub's
  markdown API, so the "proof" screenshot shows what a reviewer will actually see.

## Risks / Trade-offs

- A new dev dependency touches `bun.lock`. Verified safe: `bun install --frozen-lockfile`
  reports no changes, and Playwright has no install hooks.
- Screenshots in `docs/screenshots/` add ~340 KB to the repo. Acceptable for the evidence
  value; they are regenerated by `npm run e2e`.
