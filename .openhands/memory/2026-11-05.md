## Cloudflare build failure: bun lockfile version (fixed, v0.2.17)
- Symptom: CF Workers Build aborts at `bun install --frozen-lockfile` with
  "Unknown lockfile version ... at bun.lock:2:22" then "lockfile had changes, but
  lockfile is frozen". Cause: the committed `bun.lock` was `lockfileVersion: 2`,
  which the build image's bun 1.2.15 cannot parse, so it discards the lockfile and
  the frozen check then fails.
- Fix: regenerate with the SAME bun version the builder uses (1.2.15 -> emits
  `lockfileVersion: 1`) and commit. Verify by reproducing locally: download the
  exact bun from the GitHub release zip (`python3 -c "import zipfile..."`, no unzip
  binary needed), then `bun install --frozen-lockfile` must print "no changes".
- The build image's tool versions are in the CF build log header ("Detected the
  following tools from environment: bun@X, nodejs@Y") - match bun to that.

## CloudTube deploy/monitoring facts
- `main` auto-deploys via **Cloudflare Workers Build** (not GitHub Actions; there is
  no .github/workflows). A push ships in ~1-2 min.
- No CF credentials in the sandbox (`cf` CLI absent, no wrangler login, no
  CLOUDFLARE_API_TOKEN) and `.openhands-setup/cloudflare/restore.sh` says MCP OAuth
  and `cf auth login` cannot be completed headless - the owner must approve in a
  browser. So the agent cannot read CF build logs directly; monitor with
  `curl -s https://ct.devmatrix.top/api/health` (returns version/tag/commit) and by
  grepping the served bundle at `/assets/index-*.js`.
- Release flow: every push to main must be a release. `node scripts/release.mjs patch`
  then push main + the tag. It needs full history + tags (the clone was shallow:
  `git fetch --unshallow --tags`). It computes the next version from `git describe`,
  so **fetch tags before releasing** or you will collide with a tag another session
  already pushed (happened: local cut v0.2.18 that already existed -> had to redo as
  v0.2.19). Then `npm run deploy:log -- --env production --url https://ct.devmatrix.top
  --notes "..."` and commit the ledger.
- There is a SECOND agent session working this repo concurrently (it added
  `.openhands-setup/cloudflare/` and cut v0.2.18). Always `git fetch` before release.
