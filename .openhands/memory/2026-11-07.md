## Editor: "Add from your library" dropdown
- Added a dropdown of **saved videos with a direct media URL** (`playback.previewUrl`) that
  adds the chosen one as a clip via `readClipFromUrl`. New: `src/components/editor/LibraryClipPicker.tsx`,
  `readClipFromUrl` + `isEditableVideo` + `editableLibraryVideos` in `src/services/videoEditor.ts`,
  `EditorView` now takes a `videos` prop (passed from `src/App.tsx`).
- **Only RedGifs saved clips qualify.** Verified `https://media.redgifs.com/*.mp4` sends
  `access-control-allow-origin: <origin>` (reflects) and supports range requests, so a browser
  `fetch()` can read the bytes. Catalogue (Vega/Vortex) videos are iframe-only with no direct URL;
  YouTube likewise — so they are filtered out.
- Verification: 63 unit tests (added isEditableVideo/editableLibraryVideos/readClipFromUrl cases,
  fetch stubbed for the readable/non-media/blocked cases), 6 Playwright tests (added a dropdown
  test using a same-origin fixture as the "saved video"), tsc + vite build clean,
  `openspec validate --all --strict` passes.

## Editor: built-in sample clips (public/samples)
- Added three small MP4s under `public/samples/` (test pattern 5s, colour bars 5s, gradient 8s),
  generated with ffmpeg (libx264 + aac, 640x360). Vite copies `public/` into `dist/`, and the
  Worker's ASSETS binding serves them, so committing them IS the "upload to Cloudflare" step.
  Total ~363 KB.
- `src/data/sampleClips.ts` lists them; the picker (`LibraryClipPicker`) shows an optgroup
  "Samples (built in)" always, plus "Your library" when editable saved videos exist.
- Same-origin ⇒ always readable (no CORS), so a sample can be added AND exported end-to-end
  in Playwright with no local file (new e2e test asserts a 5s export).
- ffmpeg is not preinstalled in the sandbox; `sudo apt-get update && sudo apt-get install -y ffmpeg`.

## Inline search playback + Settings-only source selection (v0.2.50)
- **Removed the "Also search:" source chip row from `SearchView`.** It duplicated the
  `Settings → Search Sources` picker and edited the same stored preference
  (`src/services/searchSources.ts`). Search still *reads* the selection and re-reads it on change
  (`subscribeSearchSources`); the page now just prints "Searching the N sources you enabled in
  Settings… Change them under Settings → Search Sources." Failed sources are shown as ONE
  non-blocking note (via `openSourceById(id).name`), not per-chip ⚠ marks.
- **Search results play in place.** New `src/components/SearchResultCard.tsx` owns one `isPlaying`

  "Stop" returns the poster; "Full page" calls `onPlayVideo(video, resultQueue, 'Search results')`
  exactly as before (queue still walks the results).

  full player (`allow-scripts allow-same-origin allow-presentation`, `strict-origin-when-cross-origin`).
